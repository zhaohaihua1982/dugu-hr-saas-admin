## 1. 菜单 sys_menu

单表树（parent_id 自引用），不建 role_menu 关联——权限过滤是下一期的事，本期菜单只服务"系统后台长什么样"。

**action 的预留方式**：`type=3` 即动作节点，`action_code` 放在同一行。全局唯一用生成列实现（MySQL 无部分唯一索引，与 `sys_user.deleted_at` 参与唯一键同一手法）：

```sql
action_uniq VARCHAR(64) GENERATED ALWAYS AS (
    CASE WHEN action_code <> '' AND deleted_at = 0 THEN action_code ELSE NULL END
) STORED,
UNIQUE KEY uk_action (action_uniq)
```

非 action 节点 `action_code=''` → 生成列为 NULL，唯一索引不去重，互不冲突；action 节点非空 → 全局唯一。**后面加 action 配置时不需要改表**，只需要在应用层放开 type=3 的管理入口。

其他约束：
- 删除有子节点的菜单必须拒绝（`ErrMenuHasChildren`）——静默级联删是菜单误删事故的第一来源；
- `username` 式的编码字段本期不加，菜单靠 id 定位；
- 树在应用层组装（全量几十行，不需要递归 CTE）。

### 1.1 多语言：翻译放子表，`name` 作兜底

**结论：不要问到"在菜单本身填"这一步就停。** 三种做法里只有一种能长期成立：

| 做法 | 加一门语言的代价 | 判定 |
|---|---|---|
| `name` / `name_en` / `name_ja` 多列 | `ALTER TABLE` + 改 PO + 改 DTO + 改前端映射 | ❌ 列数随语言线性增长，且多数列为空 |
| `name` 存 i18n key（如 `menu.system.user`），译文进 `locales/*.json` | 改代码 + **发版** | ❌ 菜单是运营在后台配的，发版才能加翻译等于不可用 |
| `sys_menu.name` 默认语言名 + `sys_menu_i18n` 子表 | 插几行数据 | ✅ 采用 |

判断标准只有一句：**这份文案谁维护？** 错误码文案归开发（进 `pkg/i18n/locales`，随代码发版天经地义）；菜单名归运营（后台配完要立刻生效）。两类文案走两套机制，不是不一致，是各自的正确解。

**`sys_menu.name` 不是冗余，是兜底。** 回退链：

```
请求 lang 的翻译 → sys_menu.name（默认语言）→ 有 name 就永远有显示
```

若只存子表、主表不留 name，一旦某门语言漏翻，前端左侧菜单会出现**空白项**——用户当成 bug 报，排查时才发现是缺一行翻译。这条兜底必须硬性保留：`name` 永远 NOT NULL。

**哪些字段翻、哪些绝不翻：**

| 字段 | 翻 | 理由 |
|---|---|---|
| `name` | ✅ | 唯一面向用户的展示文案 |
| `remark` | 可选 | 内部备注，给管理员看，翻不翻都行（建议不翻，省维护量） |
| `path` / `component` | ❌ | 前端路由与组件路径，翻了直接 404 |
| `icon` | ❌ | 图标名是符号标识，不是文案 |
| `action_code` | ❌ | 鉴权码，翻了权限全失效 |

把 `path` 也做多语言的方案真实存在过，后果是所有菜单点不进去——因为前端路由表是按代码里的 path 写的。

**四条实现约束：**

1. **语言集合从 `pkg/i18n.Registered()` 派生**，不单独建语言配置项。否则会出现"菜单有 ja-JP 翻译、错误提示没有 ja-JP 语言包"的半吊子状态。
2. **写入前归一化 lang**（`i18n.ParseLang`：大小写不敏感、下划线视作连字符）。不归一化会让 `en_us` 和 `en-US` 存成两行，翻译查不到。
3. **唯一键 `(menu_id, lang, deleted_at)`**，与现有表一致用 `deleted_at` 参与唯一（软删后同名语言可重建）。
4. **主表 `name` 必须等于默认语言（`site_lang`）的译文**。切换默认语言时不自动改写历史 name——那会让一批菜单名突然变成另一种语言，属于数据事故；由运营自行维护。

**接口形状的关键取舍**：树/列表接口按请求 lang 解析后**只返回一个 `name`**，前端不需要知道翻译表存在；只有详情/编辑接口额外返回 `names` map 供表单回填。让前端自己挑语言，等于把回退逻辑复制到每个页面。

**与字典的一致性**：字典项的 `label` 是同一个问题（下拉选项的显示名）。本期字典按单语做，中英切换后会出现"左侧菜单英文、下拉选项中文"。若英文界面是确定需求，建议字典项按本节同一模式加 `sys_dict_item_i18n`——**同构方案，不增加理解成本**；若本期不做，至少在 §10 写明下一期补，而不是当成"字典不需要多语言"。

## 2. 系统配置 sys_config

### 2.1 为什么是 KV 而不是宽表

用户要求"不要太多字段"。KV 表（`config_group + config_key + config_value`）只有 8 个字段，**新增配置项零 DDL**——这正是配置与普通业务的区别：业务字段要约束，配置项只需要约束"值合法"。

### 2.2 两组配置与键清单

**网站配置 SITE**（展示用，不参与安全）：

| key | 默认 | 说明 |
|---|---|---|
| `site_name` | HR 管理后台 | |
| `site_logo` | '' | URL |
| `site_domain` | '' | |
| `site_port` | '' | |
| `site_icp` | '' | 备案号 |
| `site_bg` | '' | 背景图 URL |
| `site_lang` | zh-CN | |

**登录配置 LOGIN**（参考阿里云登录安全设置，全部真实生效）：

| key | 默认 | 范围 | 生效点 |
|---|---|---|---|
| `login_account_enabled` | 1 | — | 登录管线入口：方式开关 |
| `login_sms_enabled` | 0 | — | 同上；**两项至少开一个**（保存时校验） |
| `login_max_fail` | 5 | 3~20 | 失败计数锁定阈值 |
| `login_lock_minutes` | 15 | 1~1440 | 冻结时长 |

| `login_ip_blacklist` | '' | 同上 | 命中即拒 |
| `login_token_ttl_minutes` | 480 | 5~1440 | JWT exp + Redis 会话滑动 TTL |
| `login_rate_per_min` | 20 | 5~600 | 登录接口 IP 限流 |
| `login_pwd_min_len` | 10 | 8~64 | 创建/重置密码校验 |
| `login_pwd_min_kinds` | 2 | 2~4 | 同上 |

### 2.3 生效机制（本期最关键的设计）

配置的难点不在存，在**让登录管线读到新值且不逐请求查库**：

```
sys_config (DB)
   ↑ Save 时失效
[application/config.Service]  ← 内存快照 + 30s TTL（atomic.Pointer，读无锁）
   ↓ 实现 domain/config.PolicyProvider
├── cache.LoginGuard   → login_rate_per_min
├── cache.LockGuard    → login_lock_minutes（计数窗口/锁定 TTL）
├── token.Service      → login_token_ttl_minutes（JWT exp）
├── cache.SessionStore → 同上（滑动 TTL 与 exp 必须一致）
├── application/auth   → 方式开关 + IP 黑白名单
└── application/sysuser → 密码复杂度
```

三条铁律：
1. **快照读无锁**（`atomic.Pointer`），DB 故障时回退内置默认值并告警——绝不因配置库抖动拒绝登录；
2. **Save 后立即失效快照**，下次读取重建（秒级生效，无需版本号广播——管理后台配置变更低频）；
3. **IP 白名单语义**：非空时白名单外一律拒绝（参考阿里云"仅白名单 IP 可访问"），黑名单优先级更高；支持 CIDR（如 `10.0.0.0/8`）。

## 3. 字典 sys_dict_type + sys_dict_item

**分两表**。理由：类型与项的生命周期和唯一约束都不同——`uk_type(code)` 全局唯一、`uk_item(type_id, value)` 类型内唯一；单表要靠 parent_id + 生成列做两套唯一性，得不偿失。表都极简（≤9 字段）。

- 删除类型时若有项 → 拒绝（`ErrDictTypeHasItems`）；
- 读取侧按 `type_code` 取启用项（前端下拉），本期直接查库（两表各几十行，索引命中 <1ms），缓存留给下一期加。

## 4. 接口清单（全部需登录，白名单不变）

```

GET    /api/v1/admin/menus/:id          详情，含 names 全集（编辑页回填用）
```

## 6. 完整 DDL（五张表）

```sql
-- ========== 1. 菜单 ==========
CREATE TABLE IF NOT EXISTS `sys_menu` (
    `id`          BIGINT       NOT NULL COMMENT '雪花ID，应用侧生成',
    `parent_id`   BIGINT       NOT NULL DEFAULT 0 COMMENT '父菜单；0=根',
    `name`        VARCHAR(64)  NOT NULL COMMENT '菜单名称',
    `type`        TINYINT      NOT NULL DEFAULT 1 COMMENT '1目录 2菜单 3动作(action)',
    `path`        VARCHAR(128) NOT NULL DEFAULT '' COMMENT '前端路由路径',
    `component`   VARCHAR(128) NOT NULL DEFAULT '' COMMENT '前端组件路径',
    `icon`        VARCHAR(64)  NOT NULL DEFAULT '',
    `sort`        INT          NOT NULL DEFAULT 0,
    `visible`     TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '1显示 0隐藏',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
    `action_code` VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '动作编码；type=3 必填，全局唯一（uk_action）',
    `remark`      VARCHAR(255) NOT NULL DEFAULT '',
    `deleted_at`  BIGINT       NOT NULL DEFAULT 0,
    `created_at`  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at`  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    -- 生成列：仅"未删除且 action_code 非空"的行参与唯一（NULL 不去重，目录/菜单互不冲突）
    `action_uniq` VARCHAR(64) GENERATED ALWAYS AS (
        CASE WHEN action_code <> '' AND deleted_at = 0 THEN action_code ELSE NULL END
    ) STORED,
    PRIMARY KEY (`id`),
    KEY `idx_menu_parent` (`parent_id`, `sort`),
    UNIQUE KEY `uk_action` (`action_uniq`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

-- ========== 1.1 菜单多语言（§1.1）：只翻 name，其余字段绝不进这张表 ==========
CREATE TABLE IF NOT EXISTS `sys_menu_i18n` (
    `id`         BIGINT      NOT NULL COMMENT '雪花ID，应用侧生成',
    `menu_id`    BIGINT      NOT NULL COMMENT '所属菜单',
    `lang`       VARCHAR(16) NOT NULL COMMENT '已归一化的语言标签：zh-CN / en-US（写入前经 i18n.ParseLang）',
    `name`       VARCHAR(64) NOT NULL COMMENT '该语言下的菜单名',
    `deleted_at` BIGINT      NOT NULL DEFAULT 0,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    -- 软删后同名语言可重建；同一菜单同一语言仅一行
    UNIQUE KEY `uk_menu_i18n` (`menu_id`, `lang`, `deleted_at`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

-- ========== 2. 系统配置（KV，新增配置项零 DDL）==========
CREATE TABLE IF NOT EXISTS `sys_config` (
    `id`           BIGINT      NOT NULL COMMENT '雪花ID，应用侧生成',
    `config_group` VARCHAR(16) NOT NULL COMMENT '配置组：SITE / LOGIN',
    `config_key`   VARCHAR(64) NOT NULL COMMENT '配置键',
    `config_value` TEXT        NULL COMMENT '配置值（字符串）',
    `remark`       VARCHAR(255) NOT NULL DEFAULT '',
    `updated_by`   BIGINT      NOT NULL DEFAULT 0 COMMENT '最后修改人',
    `deleted_at`   BIGINT      NOT NULL DEFAULT 0,
    `created_at`   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at`   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_config` (`config_group`, `config_key`, `deleted_at`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

-- ========== 3. 字典（两表）==========
CREATE TABLE IF NOT EXISTS `sys_dict_type` (
    `id`         BIGINT      NOT NULL COMMENT '雪花ID，应用侧生成',
    `code`       VARCHAR(64) NOT NULL COMMENT '类型编码，全局唯一',
    `name`       VARCHAR(64) NOT NULL COMMENT '类型名称',
    `status`     TINYINT     NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
    `remark`     VARCHAR(255) NOT NULL DEFAULT '',
    `deleted_at` BIGINT      NOT NULL DEFAULT 0,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_dict_type` (`code`, `deleted_at`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

CREATE TABLE IF NOT EXISTS `sys_dict_item` (
    `id`         BIGINT       NOT NULL COMMENT '雪花ID，应用侧生成',
    `type_id`    BIGINT       NOT NULL COMMENT '所属类型 id',
    `label`      VARCHAR(64)  NOT NULL COMMENT '显示名',
    `value`      VARCHAR(64)  NOT NULL COMMENT '取值；类型内唯一',
    `sort`       INT          NOT NULL DEFAULT 0,
    `status`     TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
    `remark`     VARCHAR(255) NOT NULL DEFAULT '',
    `deleted_at` BIGINT       NOT NULL DEFAULT 0,
    `created_at` DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_dict_item` (`type_id`, `value`, `deleted_at`),
    KEY `idx_dict_item_type` (`type_id`, `sort`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

## 7. 领域模型要点（Go 形状，供实现对齐）

```go
// domain/menu —— 多语言只影响 name，其余字段是纯标识
type Menu struct {
    ID       int64
    ParentID int64
    Name     string            // 默认语言名（必填，兜底）
    Names    map[string]string // lang → 译文；编辑时用，展示不用
    Type     int8              // 1目录 2菜单 3动作
    Path, Component, Icon string // 绝不参与翻译
    ActionCode string
    // ...
}

// DisplayName 单一解析入口，禁止各处自己写 fallback。
// 回退顺序：请求 lang → 默认语言 → Name（永远非空）。
func (m Menu) DisplayName(lang i18n.Lang) string

// Validate 保存前校验：name 非空、names 的 key 必须是 i18n.Registered() 内语言、
// 译文长度 ≤64、单次提交语言数 ≤ 已注册语言数（防脏 key 撑爆表）。
func (m Menu) Validate() error

// domain/config —— 登录策略是核心，其他两模块是常规 CRUD
type LoginPolicy struct {
    AccountEnabled, SMSLoginEnabled bool
    MaxFailCount   int           // 锁定阈值
    LockDuration   time.Duration // 冻结时长
    TokenTTL       time.Duration // JWT exp + 会话滑动 TTL
    LoginRateLimit int           // 登录接口 IP 次/分钟
    IPWhitelist, IPBlacklist []string
    PwdMinLen, PwdMinKinds   int
}
func DefaultLoginPolicy() LoginPolicy          // 内置默认 = 配置缺失时的回退
func (p LoginPolicy) Validate() error          // 保存前校验（范围见 §2.2）
func (p LoginPolicy) IPAllowed(ip string) bool // 黑名单优先；白名单非空 = 仅白名单可登录；支持 CIDR

// PolicyProvider 登录管线的策略来源（application/config 实现，infrastructure 消费）
type PolicyProvider interface {
    LoginPolicy(ctx context.Context) LoginPolicy // 失败回退默认值 + 告警日志，绝不 panic/阻断
}
```

## 8. 管线接入点清单（精确到现有函数）

| 配置项 | 现有代码位置 | 改法 |
|---|---|---|
| 登录方式开关 | `application/auth/service.go` `LoginPassword` / `LoginSms` 入口 | 管线最前查 `policy.AccountEnabled / SMSLoginEnabled`，关闭返回新错误 `ErrMethodDisabled`（**在 IP 检查之前**，不产生任何计数） |
| IP 黑白名单 | 同上，方式开关之后、`AllowLogin` 之前 | `policy.IPAllowed(ip)`，拒绝返回 `ErrIPForbidden`；**不计失败、不写登录日志的失败计数**（写一条日志 reason=IP_FORBIDDEN 可选） |
| 登录频率 | `infrastructure/cache/session_store.go` `LoginGuard.AllowLogin` | `authn.LoginRateLimit` → `policy.LoginRateLimit`；`LoginGuard` 结构体注入 `PolicyProvider` |
| 错误次数/冻结时长 | `LoginGuard`/`LockGuard` + `application/auth` `failAttempt` | `sysuser.FailThreshold`/`sysuser.LockDuration` → policy；`LockGuard.IncrFail` 的窗口、`MarkLocked` 的 TTL 同步用 `policy.LockDuration` |
| token 有效时长 | `infrastructure/token/token.go` `Issue` + `cache/session_store.go` `SessionStore.Create/Slide` | `authn.IssueTokenTTL` → `policy.TokenTTL`；**JWT exp 与会话键 TTL 必须同源**，`SessionStore` 也注入 provider |
| 密码复杂度 | `application/sysuser/service.go` `Create` / `ResetPassword` 两处 `ValidatePassword` | 领域函数参数化：`ValidatePasswordWith(pwd, rule)`；`rule` 由 policy 映射（MinLen/MinKinds），旧 `ValidatePassword` 保留为默认规则包装（`migrate.go` seed 用默认规则即可） |

**领域常量的去留**：`domain/authn` 与 `domain/sysuser` 里的 `LoginRateLimit/IPFailLimitHour/FailThreshold/LockDuration/IssueTokenTTL` 保留为**默认值**，`domain/config.DefaultLoginPolicy` 引用它们，避免两处数字漂移。`IPFailLimitHour`（IP 撞库 50/h）本期不开放配置，保持常量。

**快照与失效**（application/config.Service 内部）：

```go
// atomic.Pointer[LoginPolicy] + 加载时间戳；TTL 30s；Save 后立即置 nil 强制重建。
// 读路径无锁；DB 出错 → 回退 DefaultLoginPolicy() + slog.Warn（绝不阻塞登录管线）。
```

## 9. 实现顺序与验收标准

实现顺序：**SQL + PO + DAO（三模块常规 CRUD）→ domain/config + 配置服务快照 → 管线接入（§8 逐行）→ 菜单/字典 application + api → 错误码/i18n → 编译**。

验收清单：

1. `go build ./...`、`go vet ./...` 通过；
2. 菜单：建树、父子约束（删父报 30032）、action_code 全局唯一（重复报 30033，两个空值不冲突）；
2b. 多语言：`GET /menus/tree?lang=en-US` 返回英文 name；某菜单只填了中文时该请求回退返回中文（**不返回空串**）；`names` 传 `ja-JP`（未注册）报 30035；`name` 传空报 30036；同一菜单同一语言重复保存不产生第二行；
3. 配置：`PUT /configs/login` 把两种登录方式全关 → 30051；改 `login_max_fail=3` 后，无需重启，第 3 次密码错误即锁定；
4. 黑名单 IP 登录 → 30027；白名单非空时白名单外 IP → 30027；
5. 改 `login_token_ttl_minutes=60` 后新签发 token 的 exp ≈ 1h，且会话键 TTL 一致；
6. 字典：type code 重复报 30043；同 type 下 item value 重复报 30044；删非空 type 报 30045；
7. 全部新接口在白名单外（未登录返回 30002），**菜单树不做权限过滤**（任意登录管理员可见全量）。

## 10. 明确不做（本期边界）

- 菜单不做角色关联（`sys_role_menu`）与权限过滤；
- `action_code` 只预留唯一性，不做按钮级鉴权中间件；
- 字典不做租户隔离；**字典项 `label` 本期单语**（菜单已做多语言，两处不一致是已知取舍：英文界面下会出现英文菜单 + 中文下拉项）。若确认要英文界面，按 §1.1 同一模式加 `sys_dict_item_i18n`，**属于下一期**；
- 字典读取侧不加缓存（两表各几十行，索引命中 <1ms）；
- 菜单多语言**不做语言自动回填**：新增一门语言不会给存量菜单批量生成译文（机器翻译质量不可控，宁可显式留空回退默认语言）；
- 网站配置只存不生效（logo/主题等由前端读 `GET /configs` 自行渲染）；
- 不做配置变更审计日志（复用现有 `log.Audit` 打点即可）。

### 11.2 校验与结构约束（实现定稿）
| 约束 | 结果码 |
|---|---|
| 主表 name 空 | `30036`（接口层 binding 先拦截为 400，`30036` 是领域兜底） |
| names key 未注册 / 归一化失败 | `30035`（写入前 `i18n.ParseLang` 归一：`en_us`→`en-US`） |

| **类型×层级矩阵（v0.2 定稿）** | 目录：父=根或目录；**菜单：只能挂目录**（不能作根/不能挂菜单）；动作：父=目录或菜单、**不能作根、不计入层级** |
| 父节点不存在 / 父是动作 / 以自己为父 / 父链成环 | `30034` |
| 树深超限——**只统计目录+菜单**（动作不算）：dir/menu 链 > 3 级 | `30034`（防恶意深树；动作挂 3 级节点下不违规） |
| 有子节点时删除 / 改 type | `30032` |
| path/component/icon/remark 超长（DDL 上限） | `30034` |

- 环/深度检测：全量 `ListAll` 内存判定（菜单百级数据，避免逐层 N 次查询）；
- 动作是叶子：任何节点不能挂在动作节点下（`30034`）。

### 11.3 多语言（§1.1 落地）
- `names` 只覆盖所传语言（未传语言不动）；同一菜单同一语言重复保存不产生第二行（`uk_menu_i18n` upsert 实测）；
- 树展示名回退链实测：`?lang=en-US` 有译文回译文，无译文回主表 name（**永不返回空串**）；
- 语言集 v1.1 起 = `zh-CN / zh-TW / en-US`（前端固定三语言，管理模式详见《前端多语言与菜单接口协同修改建议.md》；embed 扫描 locales 自动注册）；
- **接口字段类型约定**：`visible` 在 JSON 中是 boolean（DB 存 TINYINT(1)，接口层转换），`status` 是整数枚举（1启用/0停用），不得以 0/1 表达 visible；

- 译文子表随主表软删同事务处理。
