# 前端多语言与菜单接口协同修改建议

> 版本 v1.2 · 范围：管理后台菜单名称多语言及菜单 v0.4 接口协同
> 创建：2026-11-09 · 最后修改：2026-11-10
> v1.1：§3 全部采纳并实施（zh-TW 语言包 / visible 布尔约定），实施记录见 §6（验收五项全过）
> v1.2：前端已适配 `code/id_path/created_at` 与三语言；补充服务端基线 SQL/响应注释一致性建议

## 1. 背景

管理后台前端固定支持三种界面语言：`zh-CN`、`zh-TW`、`en-US`。

多语言文案分为两类：

1. 菜单名称、动作名称由运营在 `sys_menu` / `sys_menu_i18n` 中配置，服务端按 `GET /api/v1/admin/menus/tree?lang=` 返回已解析的 `name`；
2. 表格标题、分页、表单与详情字段、按钮、校验提示等固定界面文案由前端 `src/locales` 维护。

两类文案不能混用：服务端返回的菜单名称不得再次作为前端 i18n key 翻译；固定页面字段不得存入 `sys_menu_i18n`。

## 2. 历史差异（已解决）

服务端原先只注册 `zh-CN`、`en-US`，现已注册：

- `zh-CN`
- `zh-TW`
- `en-US`

`application/menus.normalizeNames` 严格要求 `names` 的语言键存在于 `i18n.Registered()`。以下请求现已可以正常提交：

```json
{
  "names": {
    "zh-TW": "選單管理"
  }
}
```

前端繁体界面现在直接请求 `lang=zh-TW`，不再映射为 `zh-CN`。

## 3. 已实施修改

### 3.1 注册繁体中文

新增文件：

```text
pkg/i18n/locales/zh-TW.json
```

内容应覆盖现有 `zh-CN.json` 的全部错误码及通用消息键，翻译为繁体中文。语言包由 `embed locales/*.json` 自动扫描，无需新增独立语言配置表。

新增后，以下能力会自动生效：

- `i18n.Registered()` 包含 `zh-TW`；
- `i18n.ParseLang("zh-TW")` 返回成功；
- 菜单新增、修改接口接受 `names["zh-TW"]`；
- `GET /api/v1/admin/menus/tree?lang=zh-TW` 返回繁体名称，缺失时按既有规则回退 `sys_menu.name`；
- 请求头 `Accept-Language: zh-TW` 可返回繁体业务错误信息。

### 3.2 保持接口字段类型一致

菜单接口当前 `visible` 的真实 JSON 类型为布尔值：

```json
{
  "visible": true
}
```

建议服务端设计文档、接口示例和后续 OpenAPI 定义统一使用 `boolean`，不要与数据库的 `TINYINT(1)` 表达混为 `0/1`。

`status` 继续使用整数枚举：`1=启用`、`0=停用`。

## 4. 前后端职责约定

| 文案类型 | 来源 | 示例 |
|---|---|---|
| 菜单/目录/动作名称 | 服务端 `sys_menu_i18n` | 用户管理、登录日志、新增菜单 |
| 页面固定标题和字段 | 前端语言包 | 姓名、状态、创建时间、操作 |
| 分页和通用按钮 | 前端语言包 | 首页、末页、共 N 条、保存 |
| 服务端业务错误 | 服务端错误码语言包 | 菜单存在子节点，禁止删除 |
| 业务数据内容 | 原始数据或业务字典 | 用户姓名、IP、日志内容 |

## 5. 验收标准

1. `i18n.Languages()` 返回 `zh-CN`、`zh-TW`、`en-US`；
2. 创建菜单时提交三种名称成功；
3. 分别请求三种 `lang`，同一菜单返回对应的 `name`；
4. 缺少 `zh-TW` 翻译的菜单回退主表 `name`，不得返回空字符串；
5. `visible` 请求和响应均为 JSON 布尔值；
6. `go build ./... && go vet ./...` 通过。

## 7. 菜单 v0.4 后续一致性建议（2026-11-10）

前端已按服务端 `application/menus.NodeView` 完成以下适配：

- `action_code` 改为 `code`；
- 接收只读字段 `id_path`、`created_at`；
- 动作节点提交时保持 `path=code`；
- 菜单和动作校验 `code` 必填，目录创建允许留空；
- `names` 表单覆盖 `zh-CN / zh-TW / en-US`；
- 接入 `POST /api/v1/admin/menus/sort`。

服务端仍建议处理两处非阻塞一致性问题：

1. `config/sql/sys_menu.sql` 的建表基线尚未声明 `id_path`，当前依赖 `migrate.go.ensureColumns` 在启动时补列。建议基线 DDL 同步增加 `VARCHAR(2048) NOT NULL DEFAULT ''`，避免新库结构需要二次补齐；
2. `NodeView.Children` 使用 `json:"children,omitempty"`，叶子节点实际会省略 `children`，但代码注释仍写“`[]` 非 null”。建议统一注释与真实响应；前端已按可选字段兼容。

口诀（§4 职责表）不变：菜单名归服务端子表，页面固定文案归前端语言包，两类不得互串。
