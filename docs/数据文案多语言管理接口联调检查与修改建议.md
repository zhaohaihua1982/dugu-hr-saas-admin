# 数据文案多语言管理接口联调检查与修改建议

> 检查日期：2026-11-10  
> 依据：`docs/基础设施-数据文案多语言(i18n)设计.md` v1.2

## 1. 当前结论

服务端当前代码已经注册以下 6 个接口，前端可按 v1.2 契约直接联调：

```text
GET    /api/v1/admin/i18n/meta
GET    /api/v1/admin/i18n/texts
PUT    /api/v1/admin/i18n/texts
DELETE /api/v1/admin/i18n/texts
POST   /api/v1/admin/i18n/texts/batch-delete
GET    /api/v1/admin/i18n/pending
```

已确认的实现位置：

- 路由：`routes/router.go`
- Handler：`api/v1/i18n.go`
- 用例与 DTO：`application/i18n/service.go`
- 资源注册表与校验：`domain/i18n/i18n.go`

因此当前不是“路由完全缺失”，而是还存在以下影响前端完整功能的契约问题。

## 2. P0：缺译清单必须返回下一游标

当前 `GET /i18n/pending` 只返回：

```json
{
  "resType": "menu",
  "lang": "en-US",
  "items": []
}
```

服务端先用 `ListIDs(afterId, limit)` 取一页资源，再过滤掉已有译文。如果这一页资源都已翻译，`items` 会为空，但后面仍可能存在缺译数据。前端无法知道本次扫描到哪个 ID，也无法继续翻页。

建议响应增加服务端扫描游标和是否还有资源：

```json
{
  "resType": "menu",
  "lang": "en-US",
  "items": [],
  "nextAfterId": "2120000000000000020",
  "hasMore": true
}
```

规则：

- `nextAfterId` 取本次 `ListIDs` 返回的最后一个 ID，不取 `items` 最后一项；
- `hasMore` 表示主资源是否还有下一页，不表示当前是否存在缺译项；
- 即使 `items=[]`，只要 `hasMore=true`，前端仍可继续请求；
- 雪花 ID 必须按字符串返回。

## 3. P0：统一成功响应示例

项目请求层以 `{status: 200, msg, data}` 判断成功，`ctl.RespSuccess` 当前也应保持 `status=200`。设计文档 §7.5 的示例写成了 `status: 0`，容易让前端或测试按错误值实现。

建议将设计文档示例统一为：

```json
{ "status": 200, "msg": "操作成功", "data": {} }
```

## 4. P1：权限接入

译文写接口本质上可以修改菜单名和字典项显示文案。按钮级 RBAC 上线前，建议路由暂时只允许超级管理员访问；RBAC 上线后按 `registry[resType].Resolver.PermWrite()` 叠加资源写权限：

```text
menu      -> menu:update
dict_item -> dict:update
```

不能只校验通用的 `i18n:write`，否则会绕过资源模块自身权限。

## 5. 批量删除契约确认

前端按当前 DTO 提交四元组列表，最多 200 项：

```json
{
  "items": [
    {
      "resType": "menu",
      "resId": "2120000000000000001",
      "field": "name",
      "lang": "en-US"
    }
  ]
}
```

响应：

```json
{ "status": 200, "msg": "操作成功", "data": { "deleted": 1 } }
```

应保持单事务全成功或全失败，并保持重复删除幂等。

## 6. 联调验收重点

1. `GET /meta?resType=menu` 返回字段上限、三种语言和默认语言；
2. `GET /texts` 的默认语言只出现在 `defaultValue`，不出现在 `texts`；
3. `PUT /texts` 只覆盖提交的语言，空串走软删；
4. 不存在的资源 ID 返回 `30040`，且不产生孤儿译文；
5. 单条删除重复调用均成功；
6. 批量删除 200 项成功，201 项整体拒绝；
7. `pending` 即使当前扫描页无缺译，也能通过 `nextAfterId` 继续；
8. 三种 `Accept-Language` 下错误消息正确，成功数据字段结构不变。
