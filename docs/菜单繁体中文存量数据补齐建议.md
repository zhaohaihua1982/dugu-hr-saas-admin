# 菜单繁体中文存量数据补齐建议

> 版本 v1.1 · 范围：`sys_menu_i18n` 存量数据补齐
> 创建：2026-11-10 · 最后修改：2026-11-10
> v1.1：§3 方案已实施（启动期幂等补齐，application/menus/backfill.go），实施与验收记录见 §6

## 1. 问题结论

前端切换繁体中文时已正确请求：

```http
GET /api/v1/admin/menus/tree?lang=zh-TW
```

当前数据库共有 40 个有效菜单节点：

- 15 个目录/菜单节点（`type=1/2`）；
- 25 个动作节点（`type=3`）。

25 个动作节点均已有 `zh-TW` 译文，但 15 个目录/菜单节点中只有“用户管理”存在繁体译文，其余 14 个缺失。服务端按既定回退规则返回 `sys_menu.name`，因此界面出现繁体与简体混排。这不是前端语言切换问题。

## 2. 需要补齐的数据

以稳定的 `path` 定位菜单，不要使用可能被运营修改的 `name` 定位。

| path | 当前默认名称 | zh-TW |
|---|---|---|
| `/organization` | 组织管理 | 組織管理 |
| `/permission` | 权限管控 | 權限管控 |
| `/permission/menus` | 菜单管理 | 選單管理 |
| `/tenant` | 租户管理 | 租戶管理 |
| `/tenant/list` | 租户列表 | 租戶列表 |
| `/tools` | 基础工具 | 基礎工具 |
| `/tools/files` | 文件管理 | 檔案管理 |
| `/operations` | 系统运维 | 系統維運 |
| `/operations/site` | 网站配置 | 網站設定 |
| `/operations/login` | 登录配置 | 登入設定 |
| `/operations/dictionary` | 字典工具 | 字典工具 |
| `/operations/audit` | 审计日志 | 稽核日誌 |
| `/operations/login-logs` | 登录日志 | 登入日誌 |
| `/operations/operation-logs` | 操作日志 | 操作日誌 |

“用户管理”当前已有 `zh-TW=使用者管理`，不得重复覆盖。动作节点译文已经完整，本次不处理。

## 3. 推荐实现

在服务端增加一次幂等的存量数据补齐逻辑，随迁移或明确的一次性维护命令执行：

1. 按上表 `path` 查询有效 `sys_menu`；
2. 使用 `MenuRepository.NamesByIDs` 批量读取现有译文；
3. 仅当目标菜单不存在有效 `zh-TW` 时，调用 `MenuRepository.UpsertNames` 写入；
4. 已有非空 `zh-TW` 一律保留，不能用内置译文覆盖运营修改；
5. 缺少对应 `path` 时记录警告并继续处理其他项，最终输出成功、跳过、缺失数量；
6. 重复执行结果必须稳定，不新增重复译文行。

伪代码：

```go
for _, item := range traditionalMenuNames {
    menu := menusByPath[item.Path]
    if menu == nil {
        warnMissing(item.Path)
        continue
    }
    if strings.TrimSpace(existing[menu.ID]["zh-TW"]) != "" {
        continue
    }
    if err := repo.UpsertNames(ctx, menu.ID, map[string]string{
        "zh-TW": item.Name,
    }); err != nil {
        return err
    }
}
```

建议复用现有仓储和雪花 ID 生成器，不建议直接写裸 SQL：直接插入需要自行生成 `sys_menu_i18n.id`，也容易绕过既有语言归一化与重复处理逻辑。

## 4. 安全要求

- 只新增缺失的 `zh-TW`，不得修改 `zh-CN`、`en-US` 或主表 `sys_menu.name`；
- 不删除任何译文，不复活已软删数据；缺失时创建新有效行；
- 不根据中文名称匹配菜单，避免重名或运营改名导致写错节点；
- 不修改 `path`、`code`、`id_path`、层级、状态或排序；
- 不为此新增公开接口；现有菜单修改接口已经支持后续人工维护。

## 5. 验收标准

### 5.1 数据完整性

以下查询结果必须为 `0`：

```sql
SELECT COUNT(*)
FROM sys_menu m
WHERE m.deleted_at = 0
  AND m.type IN (1, 2)
  AND NOT EXISTS (
      SELECT 1
      FROM sys_menu_i18n i
      WHERE i.menu_id = m.id
        AND i.lang = 'zh-TW'
        AND i.deleted_at = 0
        AND i.name <> ''
  );
```

### 5.2 接口验收

携带有效管理端 Token 请求：

```http
GET /api/v1/admin/menus/tree?lang=zh-TW
```

15 个目录/菜单节点的 `name` 应全部为上表繁体名称，不再出现“权限管控、菜单管理、文件管理、网站配置、登录日志、操作日志”等简体回退值。

同时验证：

- `lang=zh-CN` 返回值不变；
- `lang=en-US` 返回值不变；
- 连续执行两次补齐逻辑，第二次全部为跳过且数据行数不增加；
- 人工修改某个 `zh-TW` 后再次执行，不覆盖人工值；
- `go build ./... && go vet ./...` 通过，并补充幂等与“不覆盖已有译文”测试。
